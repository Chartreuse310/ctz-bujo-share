# Agent Note: hashtag-extraction-revision-and-phd-tag

Status: implemented

## Problem

上一条笔记（feature/2026-10-14-ingestion-convention.md）定下的 hashtag 提取规则「只认井号后紧跟非空白字符」假设 tag 是单个词。第一次真实录入测试中用户输入 `博士学位论文 #PhD V2.0 P1.1`，tag 名含空格，该规则提取出 `["PhD"]`，丢掉了 `V2.0 P1.1`——规则被当场证伪。同时用户决定删除 tag「论文阶段」、改用含版本号的新 tag，触发 slug 永久性与登记表影响面问题。

## Decision

§11.1 ② 的 hashtag 定界改为三条顺序规则，且 AGENTS.md §5.5 同步：① 只从「独立成行 / 行尾的元数据行」提取，正文行里的 `#` 一律不动；② tag 从 `#` 延伸到行尾，因此 tag 名可含空格（`#PhD V2.0 P1.1` → `PhD V2.0 P1.1`），「遇空格即止」被明文标记为错误；③ `#` 后须紧跟非空白字符（`# 跑步` 是 Markdown 标题语法，不提取）。规则①是规则②的前提，不可拆开单用。同时按用户三项决定执行：tag「论文阶段」（thesis-stage）从登记表删除，由「PhD V2.0 P1.1」（slug `phd-v2-0-p1-1`，点号因 slug 正则改连字符）取代；用户明确选择「每版一个 tag」并知情接受 slug 永久停在 V2.0 或 tag 随版本膨胀的代价。已同步设计文档（更新记录、§4.3、§5.1 示例、§7、引用示例）与实现计划（Task 2.1 taxonomy、示例条目 tags 加引号、e2e 断言 tag/phd-v2-0-p1-1）；12 份 demo 与 docs/ideas/ 历史档按既有边界不动。本文取代 2026-10-14-ingestion-convention.md 中「hashtag 只认井号后紧跟非空白字符」的旧口径，其余决策（emoji 保留、type 推断+告知、tag 克制）不变。
## Alternatives considered

**「# 延伸到行尾」单用（无行角色前提）**：能正确提取含空格 tag，但正文行 `今天 #跑步 很爽，还聊了 #播客` 会整行吞成一个 tag——实测证伪，故必须以规则①为前提。**「遇空格即止」**：对正文行安全，但把 `#PhD V2.0 P1.1` 截成 `PhD`，丢失用户声明的一半——正是本次被证伪的旧规则。**「tag 不带版本号」**：能避免 URL 永久停在 V2.0 的代价，但用户明确选择「就是要每版一个 tag」，接受膨胀代价；不采纳。**「用下划线代替空格」**：改变用户输入习惯且 name 本就允许空格，无必要。**「每条录入都问 type」或「静默推断」**：前者多一轮往返、后者判错导致统计错位且难发现，均已在 2026-10-14-ingestion-convention 中否决，本次不变。
## Consequences

换来的：录入规则第一次被真实输入检验过，含空格 tag 可无损提取；用户明确了版本追踪走「每版一个 tag」。代价：① 规则①「独立行/行尾」靠纪律执行，构建期无法机械校验 Agent 是否遵守；② V3.0 出现时 URL 停留在 phd-v2-0-p1-1 或登记表 tag 膨胀，都是用户已知情接受的长期成本；③ 构建期兜底（§7 近似提示、可复制登记片段）仍未实现，错写文件仍只有「列出候选」的报错。
