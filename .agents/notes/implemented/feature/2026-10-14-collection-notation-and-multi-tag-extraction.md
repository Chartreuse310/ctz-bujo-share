# Agent Note: collection-notation-and-multi-tag-extraction

Status: implemented

## Problem

§11.1 只定义了 tag 的提取与匹配规则，集子在原始输入里怎么表示完全没有定义——上次测试里「博士学位论文」恰好是元数据行行首的独立词才被认出，正文提到集子名会误匹配，这个空白必须由用户拍板。用户随后补定：集子一般写在最后一行第一个（tag 之前），且忘写时要被提醒。

## Decision

设计文档 §11.1 新增 ①′「集子的三种情形」：用户固定写法是集子写在**最后一行（元数据行）行首**、tag 之前；三情形与 tag 对称——行首写了对得上（仅空白/全半角/大小写差异）自动归一匹配；写了对不上问用户（新建集子门槛更高，引 §11 第 2 条）；**没写但内容明显属于某已登记集子必须提醒**（用户明确要求；「宁多问一次，不错归一个」——错归会在集子页与统计里永久多计数）。没写且内容不属于任何集子 = 合法默认「日常」，不是遗漏。边界：只认元数据行第一个 token 为集子候选，集子写在 tag 后不提取；正文提到集子名不触发匹配。同轮实测定型一行多 tag 定界：tag 从 `#` 延伸到**下一个 `#` 或行尾**（`绘画 #跑步 #播客` → `["跑步","播客"]`；`#PhD V2.0 P1.1 #论文写作` → `["PhD V2.0 P1.1","论文写作"]`），替换上一条笔记的「延伸到行尾」表述（单 tag 场景两者等价，多 tag 场景后者才正确）。AGENTS.md §5.5 同步两表。本文修订 2026-10-14-hashtag-extraction-revision-and-phd-tag.md 中的定界表述。
## Alternatives considered

**把集子当 tag 一样在任意位置匹配**：会把正文里提到的「绘画练习」误判成集子引用，用户固定写法本就在元数据行，任意位置匹配徒增误报——不采纳。**要求集子也用前缀符号（如 @绘画）**：更机械可靠，但用户实际习惯是裸词行首，强加符号改变输入习惯——不采纳，裸词 + 行首位置已足够判别。**「延伸到行尾」保留原表述**：单 tag 场景与「到下一个 # 或行尾」等价，但一行写多个 tag 时会把第二个 tag 连同分隔符吞进第一个——实测 `绘画 #跑步 #播客` 口径 A 只得到 1 个 tag，故改为「到下一个 # 或行尾」。**「每个条目都问集子」**：用户只要求忘写时提醒；每条都问会让「日常」默认值的合法场景多一轮往返——不采纳。
## Consequences

换来的：录入层最后一个空白（集子怎么从原始输入识别）补齐，tag/集子两套规则对称、可执行；一行多 tag 从此有实测依据的定界口径。代价：① 规则 3「明显属于某集子」仍是 Agent 判断，构建期无法机械校验——这是录入层一贯的「纪律而非机制」性质；② 元数据行行首裸词依赖用户维持固定写法，若某天集子写在别处将静默不提取（有规则 3 的提醒兜底）；③ hashtag 定界正则比「延伸到行尾」略复杂，实现期需按 §11.1 的实测用例写单测（含空格 tag 与双 tag 组合两组）。
