## 1. 目标与成功标准

**要做什么**：一个公开的线上日记与思考分享站，把 bujo（Bullet Journal）的记录方式搬到 Web：首页是月视图，点开某一天看到当天的条目与日总结；集子和 tag 都是可浏览的入口；另有一页统计，按集子、tag、日期对比事件数与思考数。

**给谁看**：完全公开，任何人拿到链接可访问。无登录、无权限、无后端。

**成功标准**

1. 在 `content/` 下新增一个 Markdown 文件、跑一次构建，就能在对应日期、集子页、tag 页、统计页看到它。
2. 首页月视图能直观看出哪天有内容、哪天没有；点某天能展开当天全部条目与日总结。
3. 统计页能回答「本月哪个集子写得最多」「某个 tag 逐月是涨还是落」。
4. 内容写错字段（比如 type 拼错、日期格式不对）在构建时**报错并指出文件**，而不是静默生成一个坏页面。

**明确不做（本期 YAGNI）**

- 在线编辑、账号、评论、RSS 之外的订阅分发
- 搜索（内容量小的时候用不上；留到有需要再加）
- 从 Obsidian 或其他外部库同步（已确认内容就放本仓库）
- 多语言、暗色模式之外的复杂主题系统
- 图片上传流水线（Markdown 里引用相对路径的图片即可）

## 2. 已确认的决策（来自讨论）

| 议题 | 决策 |
| --- | --- |
| 写作方式 | 本地 Markdown，构建成静态站 |
| 分享对象 | 完全公开 |
| 集子 vs tag | 集子**一对一**（像文件夹）；tag **多对多**（像关键词） |
| 事件 vs 思考 | 只是类型标记，字段完全相同；分开只为统计分别计数 |
| 日总结 | **独立类型**，一天一条，**不进主时间轴**，只在月视图/日视图出现 |
| 统计重点 | 横向对比（集子/tag 之间）+ 纵向趋势（随时间） |
| 技术路线 | **Eleventy + 自定义脚本** |
| 内容位置 | **本仓库内** |
| 首页形态 | **月视图**（月历网格），点日期展开当天内容 |
| 视觉风格 | **全套 bujo**：点阵纸 + 手写体标题 + 符号系统 |

## 3. 架构总览

```
ctz-bujo-share/
├── content/
│   ├── entries/           # 事件与思考：一个文件一条
│   │   └── 2026-10-14-读完某本书.md
│   └── daily/             # 日总结：一天一条
│       └── 2026-10-14.md
├── lib/                   # 纯函数层（可单测，不依赖 Eleventy）
│   ├── schema.js          # front matter 校验
│   ├── load.js            # 读文件 → 归一化记录
│   ├── calendar.js        # 月历网格计算
│   ├── stats.js           # 统计聚合
│   └── slug.js            # 集子/tag → URL slug
├── src/                   # Eleventy 层：模板与页面
│   ├── _includes/
│   ├── _data/
│   │   └── site.js        # 全局数据：调用 lib/ 产出 records + stats
│   ├── index.njk          # 首页 = 当前月月视图
│   ├── month/…            # 任意月的月视图
│   ├── day/…              # 某天详情
│   ├── collection/…       # 集子页
│   ├── tag/…              # tag 页
│   └── stats.njk          # 统计页
├── styles/
├── test/                  # node:test 单测
├── .eleventy.js
└── package.json
```

**分层原则**：`lib/` 是纯函数，输入文件内容、输出普通对象，不 import Eleventy，因此可以脱离构建独立测试。`src/` 只做呈现。统计不放在模板里算，而是在构建时算成一份 JSON，模板只负责画。

**数据流**

```
content/**.md
   │  load.js 读取 + schema.js 校验（失败 → 构建报错并指出文件）
   ▼
归一化记录数组 (records, dailies)
   ├─→ calendar.js  → 月视图所需的网格数据
   ├─→ stats.js     → 统计数据（构建时算一次）
   └─→ Eleventy collections → 集子页 / tag 页 / 日页 / 月页
```

## 4. 数据模型

### 4.1 条目（事件 / 思考）

`content/entries/` 下每个 `.md` 文件一条。文件名不影响语义（日期从 front matter 取），但约定用 `YYYY-MM-DD-slug.md` 便于人读。

```yaml
---
type: thought          # 必填，只能是 event | thought
title: 关于时间轴的想法  # 必填
date: 2026-10-14       # 必填，YYYY-MM-DD
collection: 产品        # 选填；缺省归入「未分类」
tags: [bujo, 设计]      # 选填，数组，可空
---
正文，Markdown。
```

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `type` | 是 | `event` \| `thought` | 拼错即构建报错 |
| `title` | 是 | string | 非空 |
| `date` | 是 | `YYYY-MM-DD` | 决定在时间轴/月视图上的位置 |
| `collection` | 否 | string | 一对一；缺省 = 「未分类」 |
| `tags` | 否 | string[] | 多对多；缺省 = 空数组 |
| 正文 | 否 | Markdown | 允许为空（只有标题的条目） |

### 4.2 日总结

`content/daily/` 下一天一个文件，文件名必须是 `YYYY-MM-DD.md`（日期是唯一键，从文件名取，**不在 front matter 里重复写**）。

```yaml
---
title: 今天想通了一件事   # 必填，月视图上的「简述」用它
---
正文，Markdown。
```

**一天最多一条**：同名日期出现第二个文件（或 front matter 里另写日期）时构建报错。

### 4.3 三个待你拍板的模型细节

这三处我给了默认决策，实现前你可以改：

1. **集子是否必填** → 默认**选填**，缺省显示为「未分类」，且**不**触发构建错误。
   理由：日记里总有一些一时归不了类的记录，强制填会逼你随手编一个集子名，反而污染集子列表。
2. **tag 词表** → 默认**自由填写**，不做预定义词表；匹配时大小写不敏感、首尾空格忽略，展示时用**首次出现时的写法**。
   理由：个人站规模下，预定义词表是额外负担；大小写归一避免 `Bujo` 和 `bujo` 分裂成两个 tag。
3. **集子名 / tag 的 URL** → 中文名直接转 slug（保留中文，空格转 `-`），例如 `/collection/产品/`、`/tag/设计/`。
   理由：可读性优先，不做拼音转写。

## 5. 页面清单

| 路径 | 内容 | 关键点 |
| --- | --- | --- |
| `/` | 当前月月视图 | 月历网格；有内容的日期标出条目数；点日期进日页 |
| `/month/2026-10/` | 任意月月视图 | 上一月/下一月导航 |
| `/day/2026-10-14/` | 某天详情 | 当天的日总结（若有）+ 当天全部条目，按 bujo 符号区分事件/思考 |
| `/collection/产品/` | 集子页 | 该集子下全部条目，倒序 |
| `/tag/设计/` | tag 页 | 该 tag 下全部条目，倒序 |
| `/stats/` | 统计页 | 见第 6 节 |
| `/entry/<slug>/` | 条目详情 | 可选；若条目内容都很短也可只用日页展开，**待定** |

**月视图细节**

- 7 列 × 5~6 行，周一或周日起始 → 默认**周一起始**（中文习惯），可配置。
- 每格显示：日期数字 + 该日条目数 + 日总结标题（截断）。没有内容的格子保持空白，保留点阵纸的呼吸感。
- 点格子进入日页（不是弹窗），保证可分享、可深链。

**bujo 符号系统**

| 符号 | 含义 |
| --- | --- |
| `•` | 事件（event） |
| `○` | 思考（thought） |
| `×` | 已完成（本期不做完成状态，**符号先预留**） |
| `→` | 已迁移（同上，预留） |

本期只用到 `•` 和 `○`。`×` 和 `→` 需要条目上有状态字段，属于下一期。

## 6. 统计设计

统计在**构建时**算好，输出一份 JSON，页面用**手写内联 SVG** 画图（不引入客户端图表库：站点是静态的，图表数据在构建时就固定了，没必要为此加载几百 KB 的 JS）。

**统计页三块**

1. **总量卡片**：事件总数、思考总数、日总结数、有记录的天数。
2. **横向对比**：选定时间窗口（本月 / 本年 / 全部，可切换）内，按集子和按 tag 的条目数排行，横向条形图；每条同时显示事件数与思考数（堆叠或并列）。
   - 集子列表较长时显示前 N 个（默认 10）+「其他」。
3. **纵向趋势**：按月（本年）或按日（本月）的折线图，事件数与思考数两条线。

**「比较和变化」怎么体现**

- 横向：同一时间窗口内，集子/tag 之间的条目数差异（排行条）。
- 纵向：时间序列的涨落（折线）。
- 变化率：每个集子/tag 在「本期 vs 上期」的增减，用 ↑/↓ 加百分比标注。上期为 0 时显示「新增」而不是「+∞%」。

**口径**

- 计数单位是**条目**（一个 Markdown 文件算一条），不是字数。
- 日总结**不计入**事件/思考统计，单独计数（因为它是独立类型）。
- 日期归属一律用 `date` 字段，不用文件修改时间。

## 7. 校验与错误处理

构建时校验，失败就**中断构建**并打印 `文件路径 + 字段 + 实际值 + 期望值`。要覆盖：

| 情况 | 处理 |
| --- | --- |
| `type` 不是 `event`/`thought` | 报错 |
| `date` 格式非法或不存在（如 `2026-02-30`） | 报错 |
| `title` 缺失或空 | 报错 |
| `tags` 不是数组 / 元素为空字符串 | 报错 |
| `collection` 不是字符串 | 报错 |
| 两条记录的 slug 冲突（如两个文件都叫 `note.md`） | 报错 |
| 日总结文件名不是 `YYYY-MM-DD.md` | 报错 |
| 同日两个日总结 | 报错 |
| 未知的 front matter 字段 | **警告**（不中断），提示可能是拼写错误 |
| `content/entries/` 为空 | 正常构建，页面显示空态文案 |

**校验实现**：用 `zod` 声明 schema。这是本项目**除 Eleventy 之外唯一引入的依赖**——手写校验器的成本主要在错误信息质量上，而错误信息正是这个项目「写错要立刻知道」的关键。若你希望零依赖，可改手写，但错误信息会朴素一些。

## 8. 视觉方向

- **底**：点阵纸背景（CSS `radial-gradient` 重复生成，不用图片，避免额外请求）。
- **字**：标题用手写体（如 Caveat / 霞鹜文楷一类可中文的选项），正文用干净的无衬线以保证长文可读性。手写体只用于标题、日期、符号。
- **符号**：`•` `○` 作为条目前缀，等宽对齐。
- **色**：克制的墨色 + 一个强调色（默认墨蓝或赭红），事件/思考用符号区分而非颜色区分，保证打印和色盲友好。
- **可达性**：正文对比度满足 WCAG AA；符号都配 `aria-label`，不靠形状单独传达语义。

## 9. 测试策略

`lib/` 是纯函数，用 `node:test` 覆盖：

- `schema.js`：每种非法输入都能被拒，且错误信息含文件路径与字段名。
- `calendar.js`：月首/月末对齐、闰年 2 月、跨年边界。
- `stats.js`：按集子/tag/日期的聚合计数正确；空数据集不崩；上期为 0 时显示「新增」。
- `slug.js`：中文、空格、大小写、重复名冲突。
- **端到端**：构建一次，断言关键产物文件存在（首页、某个集子页、某个 tag 页、统计页），并快照统计 JSON。
