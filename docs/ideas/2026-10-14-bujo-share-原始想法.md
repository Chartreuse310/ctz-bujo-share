## 0. 一句话

一个**日记 + 思考的线上分享网站**，风格参考 **bujo（Bullet Journal）系统**。

---

## 1. 核心内容（用户明确提出的三块）

### 1.1 时间轴（Timeline）

时间轴上的每一项，可以是一个**事件**，也可以是一个**思考**。

每一项包含四个字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 该项的标题 |
| 内容 | 正文 |
| 集子 | 所属「集子」（bujo 语境下的 Collection） |
| tag | 标签 |

**统计路径要求**：集子和 tag 都要能作为一条「路径」进入，
在该路径下看到所有写在这个集子 / 这个 tag 内的事件与思考。

> 即：集子和 tag 不只是分类标签，而是**可浏览的视图入口**。

### 1.2 每日总结（Daily Log）

- 结构：**标题 + 内容**
- 在**月时间轴**上，可以看到每一天的简述

> 即：日总结是「一天一个」的记录单元；月视图把每天的简述平铺出来。

### 1.3 统计（Stats）

需要能看到**事件数、思考数**在以下维度上的**比较与变化**：

- 集子（按集子比）
- tag（按 tag 比）
- 日期（随时间变化）

## 2. 记录者的理解（**待用户确认，勿当成需求**）

- 「事件 / 思考」是同一个时间轴上的两种条目类型，共享一套字段（标题、内容、集子、tag）。
- 集子（Collection）与 tag 的区别尚未澄清——两者看起来都是「归类 + 可浏览」，差别可能在于：
  - 集子是**一对一**的归属（一条只能属于一个集子）？
  - tag 是**多对多**的（一条可打多个 tag）？
  - 还是集子本身也可以有层级 / 集子 = 一个更大的主题容器？
- 「分享」的含义尚未澄清——是**公开博客**、**给特定人看**、还是**只读快照**？
- 每日总结与时间轴的关系尚未澄清——日总结本身是否也出现在时间轴上？是否也是一种条目类型？
- 「统计」的呈现形态尚未澄清——图表？数字卡片？趋势折线？

## 3. 待确认问题清单（供下一步讨论）

### 已确认（2026-10-14 讨论）

- **写作方式**：本地 Markdown 写好，发布成静态站。（→ 无后端、无在线编辑、内容在 Git 里）
- **分享对象**：完全公开，任何人可访问。（→ 无登录、无权限系统）
- **集子 vs tag**：集子**一对一**（一条记录只属于一个集子，像文件夹）；tag **多对多**（一条可打多个，像关键词）。
- **事件 vs 思考**：只是**类型标记**，两者字段完全相同。分开的意义在于统计时能分别计数。
- **日总结定位**：**独立类型**，有自己的「标题 + 内容」，**不混入主时间轴的条目流**，只在月视图出现。
- **统计重点**：横向对比（集子/tag 之间）与纵向趋势（随时间变化）**都要**。
- **技术路线**：**Eleventy + 自定义脚本**（用户选择；记录者原推荐 Astro，理由是 content collections 自带 schema 校验。选 Eleventy 的代价是 schema 校验 / 路由 / 聚合页都要自己写，需在脚本层补齐）。
- **内容位置**：**就放在本仓库里**（独立、易部署，不依赖外部笔记库）。
- **时间轴形态**：**首页 = 月视图**（月历网格），点某一天展开当天的条目与日总结。非「全部条目倒序流」。
- **视觉风格**：**全套 bujo** —— 点阵纸背景 + 手写体标题 + bujo 符号系统（• 事件 / ○ 思考 / × 完成 / → 迁移）。

## 3.5 已确认的数据模型（讨论产出，2026-10-14）

三种记录类型，**事件与思考字段相同，仅 type 不同**；日总结是第三种独立类型。

```
条目 (Entry)
├── type: event | thought        # 事件 / 思考（字段相同）
├── title: string                # 标题
├── content: markdown            # 内容
├── highlight: boolean           # 重点标记，缺省 false → 进「重点概览」月视图
├── collection: string           # 集子，一对一；不填 = 日常
├── tags: [string]               # tag，多对多（可空）；必须是已登记的
└── date: date                   # 决定它在时间轴上的位置

日总结 (Daily)
├── date: date                   # 一天一条，唯一键
├── title: string                # 标题 → 月历列表上的「简述」
└── content: markdown            # 正文
```

**关键约束**

- 一条记录**只能属于一个集子**，但可以有**任意多个 tag**。
- **不填集子 = 主集子**（默认去处）。集子是「长期大量记录的方向」，不是随手分的类。
- 事件与思考共享字段，分开只为**统计时分别计数**。
- 日总结**不进主时间轴**，独立存在于月视图；一天最多一条。
- 集子 / tag 都是**可浏览入口**：点进去看到该集子 / tag 下的全部条目。
- 集子与 tag 都登记在 `content/taxonomy.yml` 里，**显示名与 slug 分离**；引用未登记的名称会构建报错。
- **新增 tag 需要用户确认**，不自动添加。
